# RackWatch evaluation

> All data in this report is SIMULATED. The scenarios are
> deterministic labelled CSVs (seed 42, one reading per minute),
> generated by `api/src/test/resources/scenarios/generate_scenarios.py`.
> Every number below was computed by `EvaluationReplayTest` from
> those CSVs; none was written by hand.

## Method

Each scenario is replayed one reading at a time, per sensor, through
two systems: **naive** (R1 only — first out-of-range reading opens)
and **smart** (R2 threshold + R3 rate of change + R4 sensor health).
The evaluator sees the same history live ingestion would: all readings
so far for that sensor, in timestamp order.

## Metrics

- **False alarm** — an alert opened on a reading labelled NORMAL.
- **Missed incident** — a labelled incident (a maximal run of rows
  with the same non-NORMAL label on one sensor) during which no
  alert opened.
- **Detection delay** — minutes (and readings) from the incident's
  first labelled reading to the first alert opened for it. Only
  detected incidents have a delay; a missed incident has none.

## Scenarios

- **normal_day** — a full day (1440 readings per sensor) of normal
  temperature and humidity with five single-reading temperature
  spikes and two single-reading humidity blips, all labelled NORMAL.
- **cooling_failure** — 120 minutes: 30 normal, then the temperature
  ramps +0.5 C per minute for 20 minutes and holds near 32 C.
- **stuck_sensor** — 120 minutes: 30 normal, then the temperature
  sensor sticks at exactly 22.5 C (in range) for 90 minutes.
